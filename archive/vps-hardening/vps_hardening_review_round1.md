# VPS Hardening Brief — Round-1 adversarial review record (S238, 13 Jul 2026)

Three independent reviewers examined brief v1 (W1–W7b as then written). Verdicts: design attack — "does not survive contact, 2 build-breaking findings"; governance — "approvable with amendments"; pre-mortem — "loud but not survivable". Brief was rewritten to v2 in response. This record preserves the findings for closure auditing.

## A. Design attack findings (against W7/W7b as v1-written)
- **A1 CRITICAL — cross-code identity collision.** races UNIQUE(race_date, venue_normalised, race_number) has no code dimension; upsert COALESCE = last writer wins; normalise_venue strips " park"/sponsors so dog Sandown Park → sandown = horse Sandown; LIVE PROOF: Mount Gambier 2026-07-12 dog meeting (tabtouch `adx/*`) already merged into horse rows; Cranbourne 2026-07-13 = 23-race fused grid. Unguarded sweep writes could stamp a DOG market id + dog selection ids onto a HORSE race → bet settles against wrong market. Fix: sweep resolves by betfair_win_market_id, never COALESCE-overwrite a non-null market id via venue+number; key gains code at reset.
- **A2 CRITICAL — Betfair listMarketCatalogue silent 200-market cap.** With RUNNER_METADATA, max 200 results, no overflow error, FIRST_TO_START order → whole-day fetch loses everything after ~mid-afternoon. T+H alone = 90 win markets on 12 Jul; 3-code day = 400–600. W7 dogs also push the COLLECTOR's own 12h discovery window (`capture/orchestrator.py:208-215`, max 200) over the cap — W7 would degrade existing coverage. Fix: paginate via market_start_time cursor until window <200; alarm on any exactly-200 window; fix collector discovery too.
- **A3 HIGH — race_date convention.** Existing discovery stamps UTC-today (`orchestrator.py:204`); breakfast sweep (pre-00:30 UTC) would file the entire day under D-1; results/SP/scratchings from other writers then land on a different fragment → race shows, bet logs, settle-at-entry finds nothing. LIVE PROOF: Mount Gambier R1–7 dated 2026-07-11 with scheduled_start 2026-07-12T02:50Z, betfair_only, 0 runners. Fix: race_date = local racing day from marketStartTime, stated in brief.
- **A4 HIGH — sweep has no watchdog.** liveness_check checks collector-alive/betfair-fresh/api-responsive only; a dead sweep (cert expiry, OOM, bad edit) = silent regression to collector-only loggability. Fix: stamped-coverage check ("every race jumping in next N hours has market id + ≥1 runner with selection id") — also catches A2 truncation.
- **A5 HIGH — "existing upsert path" writes no runners at discovery.** Runners only created in `orchestrator._ensure_betfair_runner` (instance method, holds the only Betfair "1. Name" prefix-strip). `scripts/migrate_s_to_n_runners.py` proves the S:-key trap already burned production once. Sweep needs a shared extracted runner-write helper; acceptance asserts N: keys + clean names on all 3 codes. For dogs/harness a bad sweep write is the ONLY runner record (no subscription backfill).
- **A6 MEDIUM — venue-spelling fragmentation.** normalise_venue lacks mt→mount (LIVE: 'mount gambier' and 'mt gambier' coexist 12 Jul, Ladbrokes fields invisible to resolved race); sweep-only rows carry state=NULL. Fix: alias pairs + same-day collision audit; state handling.
- **A7 MEDIUM — picker hardcodes code=THOROUGHBRED** (race_lookup.py 5 sites) and resolves cross-code venue+number ambiguity by runner count (wrong-species resolution). v3 companion is GATING, not reference.
- **A8 MEDIUM — write contention.** No busy_timeout pragma; per-row commits; prior art: racing_api.py contention_fix §5.1 (interleaved writes degraded from second meet-write). Fix: fetch-all-then-write-burst, busy_timeout, off-peak scheduling.
- **A9 LOW/MED — "every AU market" overstated.** Trials/jump-outs/picnics unlisted by Betfair; late-added/abandoned meetings; listing times unverified. Fix: honest coverage statement + one-day calendar diff acceptance.
- **A10 LOW — shared Betfair app key.** Sweep pagination unpaced could draw TOO_MANY_REQUESTS onto collector's key. Fix: ~1s page pacing; verify fresh login doesn't disturb collector session.
